# Historical portfolio prototype readiness review

This report describes the pre-fix baseline. See [current fix status](docs/portfolio-fix-status.md) for subsequent changes and unresolved validation.

Review date: 21 October 2026. Reviewed commit: `9e0947cc4edccb094ef02ccd93c72f79d6438ba0`.

## Review outline

1. Define the portfolio prototype boundary.
2. Record executed checks and their limits.
3. List bugs, missing capabilities, and documentation gaps with evidence.
4. Set a small, measurable completion gate.

## Verdict and scope

**Promising engineering prototype; not yet ready for a dependable recruiter demonstration.** The modular services, locked dependencies, source display, streaming, persistence checks, logging, and provider-free tests provide a useful foundation. Correctness and evidence gaps currently weaken the demonstration.

The first portfolio release should demonstrate one user asking questions over a small, documented PDF collection, checking document/page evidence, receiving appropriate refusals, asking follow-up questions, and restarting without unnecessary reindexing. FastAPI, PostgreSQL, a job worker, cloud deployment, hybrid search, and reranking are optional extensions, not requirements for this release.

This is a source review with targeted reproductions, not an exhaustive guarantee that every defect has been found. Missing features below are judged against this explicit boundary or marked optional/conditional.

## Smallest credible completion gate

1. Fix P1 correctness issues and the chunk-configuration invalidation gap; add regression checks through the actual composition layer.
2. Prove unchanged restart and UI reruns do not re-embed documents, and error logs contain no test credentials or private payload markers.
3. Run the declared Python 3.12 locked quality checks and an actual Compose PDF-to-answer workflow; record exactly what was tested.
4. Evaluate a reviewed sample of approximately 20–30 real questions covering answers, unsupported requests, follow-ups, and multiple sources. Publish honest retrieval, evidence, refusal, and latency results with documented denominators.
5. Update setup/privacy/limitations/license documentation and add a short current demonstration.

Do not delay this release to implement the existing FastAPI or GCP epics. Reassess readiness after these completion gates pass; test counts alone are insufficient.
